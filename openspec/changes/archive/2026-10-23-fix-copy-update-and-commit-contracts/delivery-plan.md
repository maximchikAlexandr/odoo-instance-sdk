## Estimate evidence

- **Confidence:** medium. The estimate is **uncalibrated** because this repository provides no completed-work dataset that maps comparable task estimates to actual hours.
- **Current-code evidence:** tasks `1.1–1.2` extend the existing checkout plan, auxiliary restore, and environment lifecycle seams covered by `tests/unit/resources/test_environment_checkout.py` and the adoption suites; tasks `2.1–2.3` reuse the existing commit-message, immutable Git command, verified GitLab identity, and Multica root-creator seams; tasks `3.1–3.2` extend the existing self-update composition, snapshot, journal, and packaging fixtures rather than introducing a coordinator; task `4.1` is documentation plus established repository gates.
- **Effort concentration:** coordinated self-update is the largest position because one added companion must remain consistent across provenance inspection, frozen steps, verification, rollback/resume, and isolated-package tests. COPY is next because readiness must prove target files for ordinary and adoption paths. The bare-link change and project-aware identity wiring are bounded adaptations of existing policies and tests.

These are reflected in the authoritative property range.
- **Assumptions and exclusions:** no new subsystem, dependency, storage migration, live Odoo E2E, private test-repository mutation, screenshot workflow, or generic credential/update framework. If implementation evidence invalidates one of these assumptions, the estimate properties and topology require a planning revision.
