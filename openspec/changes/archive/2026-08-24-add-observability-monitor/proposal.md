## Why

SDK уже хранит environments всех проектов в lifecycle catalog и управляет project-level PostgreSQL cluster, но у пользователя нет единой read-only observability surface: чтобы увидеть, какие environments существуют, запущен ли Odoo, сколько ресурсов он и кластер потребляют и насколько environment разошёлся с основной веткой, приходится вручную комбинировать `odcli env list`, `odcli postgres status`, `ps` и `du`. Внешние AI factory/control-plane интеграции и сам пользователь хотят одну страницу/один JSON/один typed primitive, который собирает согласованный snapshot всех проектов, environments и cluster без side effects.

Issue #11 добавляет один `EnvironmentMonitor` collector поверх существующих catalog + `PostgresCluster` + Docker CLI + `psutil` и три режима его потребления: React+Mantine Web UI, headless FastAPI JSON API и Python SDK `snapshot()`/`watch()`. Collector — единственный владелец discovery, reconciliation и metric computation; FastAPI только сериализует typed snapshot, а UI только отображает JSON. Управляющие операции (start/stop/delete) и historical metrics остаются out of scope.

## What Changes

- **NEW capability `environment-monitor`**: один public `EnvironmentMonitor` primitive с `snapshot(project_id=None) -> Snapshot` и `async watch(interval, project_id=None) -> AsyncIterator[Snapshot]`; typed immutable `msgspec.Struct` snapshot models in `models.py` (canonical field lists in the environment-monitor spec; no public `ProcessTreeMetrics`); project discovery from catalog; monitor opaque id `project_{repo_key}`; Compose/PostgresCluster id unprefixed `repo_key`; environment list — all non-removed environments; one nullable `ClusterSnapshot` per project; Odoo process metrics via `psutil` + one-shot `/web/health` probe; Git activity vs `main`; disk footprint (`du`/`os.walk` + `psql pg_database_size`); bounded cache; component failure isolation; no secrets/absolute paths/raw Docker payload.
- **MODIFIED capability `development-environment`**: catalog получает одну current runtime-запись на environment (root PID, `psutil.Process(pid).create_time()`, started-at, checkout branch, full commit SHA, Odoo HTTP URL/port, database name); `odcli run` (через `run_foreground`) регистрирует identity после spawn и очищает в `finally`; `EnvironmentResource.list()` остаётся источником environment rows; collector читает runtime-запись и reconciles PID+`create_time` как `stopped` при stale/reused PID; schema migration v8→v9 добавляет `environment_runtime` table (одна строка на environment, upsert).
- **MODIFIED capability `server-lifecycle`**: `OdooInstance.run_foreground()` регистрирует runtime identity (root PID, `create_time()`, started-at, branch, commit SHA, HTTP URL/port, DB name) в catalog после spawn и очищает её в `finally` (включая Ctrl+C/exit 130); `start()`/`stop()`/`shell()`/`run_shell_script()` — без изменения семантики, но `run_foreground` становится единственной операцией, поддерживающей persist runtime identity (foreground run — единственный случай, где у CLI/backend есть Popen handle в том же процессе, что и catalog); `OdooClient` process registry остаётся in-memory.
- **MODIFIED capability `postgres-cluster`**: `PostgresCluster` получает read-only container identity и resource snapshot: container ID/name/image, Docker-reported init PID + PID scope (`host` на native Linux, `docker_vm` на macOS Docker Desktop/Colima, `unavailable` для stopped/missing/external), container CPU percent, memory usage/limit bytes, optional managed volume usage bytes (без privileged host traversal); external cluster не инспектируется (fields `null` с причиной `external_not_owned`); несколько managed projects собираются bounded batch `docker inspect`/`docker stats --no-stream` вызовами, а не одним subprocess на карточку; individual PostgreSQL backend PIDs не отображаются; `status()` остаётся read-only без изменения, новый resource snapshot — отдельный read-only метод.
- **MODIFIED capability `cli-odcli`**: новая команда `odcli monitor [--headless] [--host HOST] [--port PORT] [--no-open]` (замена planned `odcli dashboard`), обслуживающая FastAPI (`/api/v1/snapshot`, `/healthz`) + собранный React SPA (default loopback bind + open browser, `--no-open` suppress, `--headless` only API + `/healthz` без static assets и без browser); `odcli env list` группируется по project с одним cluster summary header и environment rows без повторения PostgreSQL PID/resources; `odcli postgres status [--json]` расширяется read-only container fields (ID/name/image, PID + scope, CPU, memory, optional volume usage) с parity к monitor cluster snapshot; JSON envelope v1 остаётся; failure одного project/environment/container не роняет list.
- **MODIFIED capability `packaging`**: optional extras `metrics` (`psutil` + collector + typed models, без FastAPI) и `dashboard` (`metrics` + FastAPI + Uvicorn); React/Mantine/Vite нужны только для build, готовые assets включаются в package (sdist + wheel) через `uv_build` data inclusion; Node.js не требуется для установленного UI/headless/SDK режима; команда без требуемого extra завершается короткой actionable install hint; container inspection переиспользует установленный Docker CLI/Compose runner из `PostgresCluster`, docker-py не добавляется; `psutil` — единственная новая runtime dependency и только за extra `metrics`.

## Capabilities

### New Capabilities

- `environment-monitor`: один `EnvironmentMonitor` collector + typed immutable snapshot/watch models; read-only discovery, reconciliation и metrics для всех catalog projects/environments и одного nullable project cluster на project; three consumption modes (SDK, FastAPI, React UI) поверх одного collector.

### Modified Capabilities

- `development-environment`: catalog current-runtime record на environment (schema v8→v9, `environment_runtime` table); collector читает её, `odcli run`/`run_foreground` пишет/чистит.
- `server-lifecycle`: `run_foreground()` регистрирует и очищает runtime identity в catalog.
- `postgres-cluster`: read-only container identity + resource snapshot (Docker inspect/stats, PID scope, CPU/RAM/volume), без изменения lifecycle.
- `cli-odcli`: `odcli monitor` (UI + headless); `env list` project grouping + cluster summary; `postgres status` container fields; JSON parity.
- `packaging`: optional extras `metrics`/`dashboard`; built React assets in package; Node.js not required at runtime.

## Impact

- **API / CLI / schema**: без breaking changes для существующих public API. `EnvironmentMonitor` и snapshot models — новые public types. Catalog schema migration v8→v9 (additive `environment_runtime` table). `PostgresCluster` получает новый read-only resource method (без изменения `status`/`ensure_running`/`stop`). `odcli monitor` — новая команда; `odcli env list` и `odcli postgres status` расширяются (additive columns/fields). Manifest schema не меняется.
- **Code**: `resources/monitor.py` — `EnvironmentMonitor`; snapshot models in `models.py`; `internal/process_metrics.py`; `internal/git_activity.py`; `internal/storage_footprint.py`; `internal/postgres_size.py`; `internal/cluster_resources.py`; `internal/serve.py`; `src/odoo_instance_sdk/web/` — React+Mantine+Vite (npm, `package-lock.json`); `cli.py` — `monitor`, `env list`/`postgres status`; catalog migration v9.
- **Security**: API не возвращает credentials, environment variables, command line, secret paths, absolute repository paths или raw Docker inspect payload; `__repr__` и exceptions остаются redacted; default bind loopback, non-loopback — explicit opt-in; CORS/auth/TLS не изобретаются внутри MVP.
- **Dependencies**: `psutil` — новая runtime dependency, только за optional extra `metrics` (не core). `fastapi` + `uvicorn` — только за optional extra `dashboard`. React/Mantine/Vite — build-time только, Node.js не требуется для установленного пакета. docker-py, PyYAML, psycopg, второй catalog, event bus, persistent metrics daemon — не добавляются.
- **Out of scope**: start/stop/restart/delete controls; agent task protocol; background supervisor или изменение foreground `odcli run`; Runbot; logs viewer (#6); resource limits/alerts/retention; распределение shared cluster CPU/RAM/volume между environments; individual PostgreSQL backend PIDs; inspection произвольного external PG; historical metrics/charts/Prometheus/Grafana; SSE/WebSocket/event bus; встроенные multi-user auth/TLS/control-plane; generic plugin/provider architecture; второй database/catalog.
