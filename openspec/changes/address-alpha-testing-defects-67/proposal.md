## Why

GitHub issue #67 collects thirteen confirmed defects from practical alpha testing of OdCLI. They span the VS Code launch profile, a missing process/resource inventory command, a divergent `env list` contract, a self-written catalogue migration chain, oversized production modules, CLI leaves that bypass the public typed SDK, documentation drift, a legacy worktree path used after the catalogue migration, project ownership lost on remote backup download, single-target-only destructive commands, raw UTC timestamps in Rich output, no detached Odoo launch, and a broken cluster identity on COPY restores. They are confirmed on the current `main`, block normal alpha workflows, and must be planned together because several items share the same SDK/CLI boundary and monitor inventory contract.

## What Changes

- **VS Code profile carries project `default_run_args`**: `odcli vscode generate` reuses the same resolved runtime/argv source as `odcli run` so safe `default_run_args` from the project manifest appear in the launch profile exactly once; empty lists add nothing; validation of disallowed managed-override families is preserved. (Item 1)
- **New `odcli ps` process/resource inventory leaf**: one read-only `odcli ps [--all-projects] [--watch] [--interval SECONDS] [--format rich|json|toon]` command that projects one canonical `EnvironmentMonitor.snapshot_command()` per sample into a frozen `ProcessInventory` model. Rich renders shared resources, the main checkout, and each environment block. PostgreSQL backend attribution is bounded to `pg_stat_activity` with explicit Linux/macOS PID-scope modelling. One bounded process-contribution contract lets `odcli-codex` (#68) and Multica (#70) add typed process groups without a plugin framework. Python SDK gains `monitor.processes_command()` / `monitor.processes()`. (Item 2)
- **`env list` becomes a checkout inventory**: the main checkout of each selected project appears as the first typed row with `kind = main | environment`; Rich drops `OBSERVED`, `ODOO_PID`, `CPU`, `RAM`, `SIZE`, and detailed process/artifact columns (they live in `odcli ps`). Rich/JSON/TOON project one frozen `CheckoutInventory` built from one snapshot per sample plus Git facts. One narrow environment-facts entry point feeds compact summaries for `odcli-codex` (#68), `odcli-openspec` (#69), and `odcli-multica` (#70) without letting extensions patch Click/Rich. (Item 3)
- **Catalogue migrations move to Alembic + SQLAlchemy Core**: one first Alembic revision creates the full current schema; clean installs skip the v2–v16 chain; known alpha catalogues are backed up, verified, and stamped; the old `PRAGMA user_version` ledger, `_run_migrations()`, `_migrate_v*`, and stale compatibility branches are removed. ORM is not added. (Item 4)
- **Split production Python files larger than 1000 lines**: behaviour-preserving refactor along confirmed responsibility boundaries for the thirteen listed files; a simple CI line-limit check with generated/vendor exclusion and no existing-file allowlist. (Item 5)
- **CLI leaves go through public typed SDK primitives**: every one of the 50 `PUBLIC_LEAF_CASES` entries gets either an `sdk_primitive` or a concrete `cli_only_reason`; catalogue reads, the test runner, dependency verification, persisted `stop`, and COPY database replacement gain public frozen input/result types and `*_command()` siblings. (Item 6)
- **SDK-first rule and documentation drift**: `AGENTS.md` gains the permanent SDK-first rule; context-resolution order is unified to the code's order; `docs/execution-boundary.md` drops the removed `--json` alias wording; README gets CI/MIT/Python 3.12+ badges; `pytest.mark.parametrize` is required for repeated input/output/error matrices; completed OpenSpec changes of this slice are synced and archived. (Item 7)
- **`run` uses the canonical `~/.odcli` worktree path**: execution plans, runtime/session ownership, provenance, and config no longer depend on the legacy `~/Library/Application Support/odoo-instance-sdk` path or its compatibility symlink; the legacy path remains only in the one-time migration/compatibility code. (Item 8)
- **Project remote-backup keeps `project_id`**: all project-owned download flows (download-only refresh and remote-backup + local-restore) record the canonical `project_id` in `start_download()` before HTTP transfer; generic SDK backup without project context stays unowned; an explicit safe relink/repair path exists for already-unowned rows; the test stops relying on manual `_RuntimeBinding` injection. (Item 9)
- **Safe multi-target deletion**: `backup rm`, `db rm`, and `env rm` accept variadic positional arguments, reuse the existing single-target resolvers/validators/builders, run one planning preflight, one confirmation, sequential execution with per-target revalidation, per-target results, and a non-zero exit on partial failure; single-target calls stay backward-compatible. (Item 10)
- **Rich absolute-time formatting in local timezone**: all absolute date/time values shown to humans in Rich are converted via `datetime.astimezone()` to local timezone and formatted as `YYYY-MM-DD HH:MM`; naive SQLite UTC timestamps are treated as UTC first; durations are untouched; JSON/TOON keep full ISO precision. (Item 11)
- **Detached Odoo launch via `odcli run -d`**: `-d, --detach` spawns Odoo, confirms the process is alive, persists runtime identity, and returns PID/identity/endpoint/log path without waiting; `odcli stop` stops that persisted runtime; logs remain reachable through the bound `odoo.conf` logfile; foreground behavior is unchanged. (Item 12)
- **COPY-restore preserves managed PostgreSQL cluster identity**: `EnvironmentManager._do_copy_restore()` binds the active managed cluster identity so `record_restore()` stores `cluster_id`; guarded drop then works for fresh COPY environments; the `None`-swallowing failure in `_remove_copy_database_command()` is replaced with a sanitized primary reason. (Item 13)

## Capabilities

### New Capabilities

- `process-inventory`: The `odcli ps` read-only leaf, its frozen `ProcessInventory` typed model, the bounded process-contribution contract for external sources, the PostgreSQL backend attribution rules, and the Python SDK `processes_command()`/`processes()` primitives.

### Modified Capabilities

- `cli-odcli`: VS Code `default_run_args` propagation, the new `odcli ps` leaf registration, the `env list` checkout-inventory contract and environment-facts entry point, multi-target deletion for `backup rm`/`db rm`/`env rm`, local-timezone Rich formatting, detached `run -d`, and the SDK-first `cli_only_reason`/`sdk_primitive` requirement on every `PUBLIC_LEAF_CASES` entry.
- `environment-monitor`: The canonical snapshot stays the single source for `odcli ps`; `ProcessInventory` and `CheckoutInventory` are typed projections of one snapshot per sample; project-owned runtime is surfaced in the inventory; PostgreSQL backend attribution and external process contributions are bounded.
- `backup-catalog`: Alembic + SQLAlchemy Core replace the `PRAGMA user_version` chain; the first revision creates the full current schema; the old migrator and stale compatibility branches are removed; `project_id` is recorded on project-owned remote downloads.
- `database-restore`: COPY-restore preserves the managed PostgreSQL `cluster_id`; `_remove_copy_database_command()` reports a sanitized primary reason instead of swallowing it.
- `database-backup`: Project-owned download flows pass the canonical `project_id` into `start_download()` before transfer; generic unowned backup remains valid; an explicit relink/repair path exists for already-unowned rows.
- `development-environment`: `env list` returns a `CheckoutInventory` with `kind = main | environment` rows; the main checkout is visible without a synthetic environment; multi-target `env rm` accepts variadic positional selectors with per-target resolution.
- `server-lifecycle`: Detached `run -d` launches Odoo, persists runtime identity, and returns without waiting; foreground semantics are unchanged.
- `instance-runtime-binding`: `run` resolves worktree paths from the canonical `~/.odcli` root; legacy paths are only used by one-time migration/compatibility code.
- `packaging`: Alembic and SQLAlchemy Core enter runtime dependencies; ORM is not added; the CI line-limit check for production Python files is introduced.
- `project-database-preparation`: Project preparation passes the canonical `project_id` into the backup download row before HTTP transfer.
- `sdk-package-imports`: The SDK-first rule and the `cli_only_reason`/`sdk_primitive` contract become a permanent architecture gate for new and changed CLI leaves.
- `local-resource-lifecycle`: The legacy `~/Library/Application Support/odoo-instance-sdk` path is no longer used for reads, writes, command construction, runtime identity, cleanup, or documentation outside the one-time migration/compatibility code.

## Impact

- Affected implementation areas: `src/odoo_instance_sdk/cli.py`, `src/odoo_instance_sdk/commands/`, `src/odoo_instance_sdk/resources/` (`environment.py`, `instance.py`, `monitor.py`, `database.py`, `postgres.py`), `src/odoo_instance_sdk/storage/backup_catalog.py`, `src/odoo_instance_sdk/internal/` (`database_preparation.py`, `database_replacement.py`, `doctor.py`, `proc/executor.py`, `pg/drop.py`, `cli_format.py`), `src/odoo_instance_sdk/models.py`, `src/odoo_instance_sdk/internal/migrations/` (new Alembic home), `AGENTS.md`, `CONTRIBUTING.md`, `README.md`, `docs/execution-boundary.md`, `docs/python-sdk.md`, `pyproject.toml`, CI workflows, and `PUBLIC_LEAF_CASES`.
- Affected tests: CLI characterization/output/watch tests, monitor inventory tests, catalogue migration tests, restore/cluster-identity tests, remote-download ownership tests, multi-target deletion tests, Rich time-formatting tests, detached-run lifecycle tests, VS Code `default_run_args` regression tests, architecture/documentation contract tests, and the new CI line-limit gate.
- Public compatibility: existing Python SDK imports, CLI command names, exit codes, JSON envelope v1, redaction, and passthrough streams remain stable. Additive public types (`ProcessInventory`, `CheckoutInventory`, and the new `*_command()` siblings) are introduced. The `env list` Rich table loses several columns and gains the main checkout row; machine output moves to `CheckoutInventory`. The catalogue migration ledger changes from `PRAGMA user_version` to Alembic; known alpha catalogues are migrated and stamped. `--json` is no longer mentioned as an alias in documentation.
- Dependencies: Alembic and SQLAlchemy Core (no ORM) become runtime dependencies. No new rendering, plugin, or framework dependency is introduced.
